## 八、测试开发面试常见问题 & 回答

### Q1：如何保证用例的覆盖率？

```
回答思路：
1. 用需求覆盖法——逐条需求对应测试用例
2. 用场景覆盖法——梳理业务流程，覆盖所有主流程和分支
3. 用等价类+边界值补充边界情况
4. 用历史缺陷数据补充高风险场景
5. 用代码覆盖率工具（JaCoCo / Coverage.py）辅助分析
6. 每次发布后复盘新增缺陷对应的场景，补录用例
```

### Q2：自动化测试失败的常见原因？如何处理？

```
回答思路：
1. 环境不稳定（网络、数据库、第三方服务）
   → 解决：Docker 化、测试前环境检查、重试机制
2. 元素定位不稳定（动态 ID、懒加载）
   → 解决：稳定定位策略（CSS/XPath 优化）、显式等待
3. 测试数据被污染（并发修改）
   → 解决：用例间数据隔离、数据准备前置
4. 版本变更导致元素/接口变化
   → 解决：PageObject 解耦、接口契约测试
5. 脚本本身有 BUG
   → 解决：代码审查、本地自测
```

### Q3：如何做性能测试？

```
回答思路：
1. 明确性能指标（RT、QPS、并发数、成功率）
2. 分析被测系统的架构，绘制数据流图，定位瓶颈点
3. 用 JMeter/Locust 编写脚本，模拟用户行为
4. 场景设计：基准测试 → 负载测试 → 压力测试 → 稳定性测试
5. 监控：CPU/内存/磁盘IO/网络/JVM/数据库连接池
6. 分析结果：TPS 拐点、响应时间分布、错误率
7. 出具报告，给出优化建议（代码/架构/配置层面）
```

### Q4：什么是测试左移/右移？

```
回答思路：
- 左移：在需求阶段就介入，提前发现需求缺陷，减少后期修复成本
  → 参与需求评审、代码审查、用测试思维评估需求可测性
- 右移：在上线后继续监控，发现生产环境问题
  → 线上监控、灰度发布验证、用户反馈跟踪、A/B 测试
```

### Q5：如何评估自动化投入产出比（ROI）？

```
回答思路：
- 高 ROI 场景：频繁回归（迭代快的项目）、核心业务流程、
  跨平台兼容测试（多浏览器/多系统）、数据驱动的批量场景
- 低 ROI 场景：一次性需求、UI 频繁变化、一次性功能
- 计算公式：
  ROI = (手工执行时间 - 自动化建设时间) / 自动化建设总时间
  × 预期执行次数
- 实践建议：先自动化高价值用例，用 PageObject 减少维护成本，
  持续集成确保脚本稳定可用
```

### Q6：接口测试如何做？

```
回答思路：
1. 分析接口文档（URL、Method、Headers、Body、Response）
2. 设计用例：正向参数、逆向参数（边界、空值、非法类型）、
   业务逻辑（状态流转、权限校验）
3. 使用 Postman / JMeter / pytest + requests 执行
4. 校验：Status Code + Body 关键字段 + 响应时间
5. 关联接口：用变量/环境参数处理接口依赖
6. 参数化：用 CSV/JSON 数据驱动批量执行
7. 集成到 CI 流水线
```
