# GM助手 Chrome 扩展 — 功能需求文档

## 1. 项目概述

### 1.1 项目名称
GM助手（GMHelper）

### 1.2 项目类型
Chrome 扩展（Manifest V3）

### 1.3 版本
3.15

### 1.4 核心功能
为游戏运营人员提供便捷的 GM 指令执行工具。通过 Chrome 扩展注入游戏后台页面，自动识别当前用户名，支持通用指令（团队共享）和个人指令（私人定制）两类 GM 指令的一键执行。

### 1.5 文件结构

```
GMHelper/
├── manifest.json        # 扩展配置（v3）
├── background.js        # Service Worker（快捷键、窗口管理）
├── content_script.js    # 内容脚本（注入GM页面，识别用户名）
├── panel.html           # 侧边面板页面
├── panel.js             # 面板核心逻辑
├── popup.html           # 弹出页面（简化版入口）
├── styles.css           # 全局样式
├── commands.json        # 本地通用指令（离线兜底）
├── devtools.html        # DevTools 页面
├── gm_backend/          # 后端服务
│   ├── server.js        # Express API 服务
│   ├── db.js            # MySQL + PostgreSQL 双库封装
│   ├── config.json      # 数据库配置
│   ├── gm-backend.exe   # 打包后的二进制
│   └── node_modules/    # 运行时依赖
└── GM助手前端扩展功能需求文档.md
```

### 1.6 技术栈

| 组件 | 技术 |
|------|------|
| 扩展标准 | Chrome Extension Manifest V3 |
| 前端 | 原生 JavaScript + CSS |
| 数据存储 | chrome.storage.local |
| 后端通信 | RESTful API (http://10.30.138.5:3000) |
| 指令注入 | chrome.scripting.executeScript |
| 后端运行时 | Node.js v24 |
| 后端框架 | Express ^4.18.2 |
| 数据库 | MySQL 8 + PostgreSQL 15（双库模式）|

## 2. 功能架构

### 2.1 四大模块

| 模块 | 说明 | 数据来源 |
|------|------|----------|
| **通用** | 团队共享 GM 指令（只读） | 后端数据库 `public` owner |
| **个人** | 用户私人 GM 指令（可编辑） | chrome.storage.local + 后端 |
| **历史** | 执行记录（最近100条） | chrome.storage.local |
| **设置** | 白名单管理、导入导出 | chrome.storage.local |

扩展面板顶部 4 个 Tab 导航：
- **通用** — 团队共享指令（只读，不可新增/修改）
- **个人** — 个人指令（可增删改）
- **历史** — 执行记录历史
- **设置** — 白名单、导入导出

## 3. 域名白名单

### 3.1 功能说明
扩展仅在白名单域名下工作，注入 GM 页面时自动检测当前域名。

### 3.2 默认白名单

```
gm.pre.nova.moonton.com
gm.nova.oa.mt
gm-cn.yyf.muyinetwork.com
gm.jp.novagames.net
gm.usa.novagames.net
```

### 3.3 域名检测逻辑

1. `content_script.js` 随 GM 页面加载，向 `chrome.storage.local` 写入当前域名 `gm_current_domain`
2. `panel.js` 启动时读取 `gm_current_domain` 和白名单
3. 匹配方式：双向子串包含匹配（`currentHost.includes(h) || h.includes(currentHost)`）
4. 不在白名单时，面板显示拒绝访问提示

## 4. 用户名识别（content_script.js）

### 4.1 功能说明
content_script 注入 GM 页面后，通过 TreeWalker 扫描 DOM 树，识别右上角/导航栏中的用户名文本，并存入 `chrome.storage.local.gm_user_name`。

### 4.2 用户名格式
- **中文+括号账号**：`封庆扬(Wis)`
- **纯英文账号**：`Wis`、`User123`
- **短英文名**：`A`、`AB`

### 4.3 黑名单过滤

**文本黑名单（精确匹配）：**
```
性能概况, undefined, null, 登录, 注册, 退出,
logout, sign out, 设置, settings, 个人中心,
用户中心, 我的, 首页, 帮助, Build #, 最近一次构建,
中文(简体), 中文(繁体), English, [TC-, TC-
```

**正则黑名单（模式匹配）：**
```
/^Build\s*#/                          → Build #1722
/^#\d+\s*\(/                          → #3 (2026年...)
/^\[TC-\d+\]/                         → [TC-04]
/^最近一次构建\(#?\d+\)/               → 最近一次构建(#305)
/^\d{4}年\d+月\d+日/                 → 2026年4月5日
/^(中文|繁體)/                        → 语言标签开头
/^(交换|天后|发送)/                    → 功能菜单
/^(移动设备|长期服务)/                 → 系统信息
/ABS\(|性能概况/                      → 监控图表
```

### 4.4 校验规则（优先级递减）

| 优先级 | 规则 | 描述 |
|--------|------|------|
| 1 | 包含 `\|` | 管道符 = 多选合并，无效 |
| 2 | 包含换行 | 多行文本，无效 |
| 3 | 正则黑名单匹配 | 系统/测试文本，无效 |
| 4 | 中文+括号英文账号 | 如 `封庆扬(Wis)`，有效 |
| 5 | 纯英文账号 3-21 字符 | 如 `Wis`，有效 |
| 6 | 短英文名 1-2 字符 | 如 `A`，有效 |
| 7 | 其他 | 无效 |

## 5. 通用指令模块

### 5.1 数据来源

1. **优先**：后端 API `GET /api/commands/public`，超时 5 秒
2. **兜底**：`commands.json` 本地文件（离线环境）
3. **初始化**：若后端无数据但本地有，自动将 `commands.json` 内容写入后端

### 5.2 指令结构

```json
{
  "装备": [
    { "name": "全身装备", "text": "add_gear %s 611210 1\n..." }
  ],
  "道具": [
    { "name": "钻石+99999", "text": "add_item %s 90001 99999" }
  ]
}
```

- Key = 分类名称（中文）
- Value = 指令数组
- `name` = 显示名称
- `text` = 实际 GM 命令（ `%s` 或 `%` 替换为角色 ID）

### 5.3 UI 布局

```
┌─────────────────────────────────────┐
│ 通用 │ 个人 │ 历史 │ 设置             │  ← 顶部 Tab
├──────┬──────────────────────────────┤
│ 分类 │ 角色ID │ 搜索GM指令...      │  ← 工具栏
├──────┼──────────────────────────────┤
│ 全部  │ ☐自动执行                    │  ← 选项行
│ 装备  │                              │
│ 道具  │ [全身装备] [全防装备]        │
│ 天赋  │ [钻石+99999] [金币+999999] │  ← 按钮网格
│ ...   │ ...                          │
└──────┴──────────────────────────────┘
```

- **左侧分类栏**：90px 宽，动态读取后端分类
- **右侧主面板**：工具栏 + 按钮网格（每行 2 个）
- **搜索**：支持中文和拼音首字母模糊匹配
- **自动执行**：勾选后点击按钮自动触发执行（无需手动点击执行按钮）

### 5.4 搜索算法

`pinyinMatch(name, keyword)` 函数：
1. 原始文本包含关键词 → 命中
2. 逐字转拼音首字母后包含关键词 → 命中

## 6. 个人指令模块

### 6.1 数据存储

| 存储 Key | 内容 | 说明 |
|----------|------|------|
| `gm_personal_commands` | 指令数组 | 个人指令列表 |
| `gm_personal_categories` | 分组数组 | 个人分组名称 |
| `gm_personal_full` | 完整数据 | 含 categories + commands |

### 6.2 同步策略

**首次加载**（本地无数据）：
- 从后端 `GET /api/commands/{owner}` 拉取
- 写入本地 storage

**后续加载**（本地已有数据）：
- 本地为准（不覆盖）
- 启动时异步推送到后端作为备份

**最大重试**：3 次，间隔 1 秒

### 6.3 个人分组

- 支持创建、编辑、删除分组
- 删除分组时，该分组下的指令自动归入"不分组"
- 分组顺序：创建顺序 + 导入顺序

### 6.4 导入/导出

**导出**：从后端拉取完整数据，生成 `gm-personal-{用户名}-{时间戳}.json`

**导入**：增量合并，不覆盖已有数据
1. 收集导入文件中的所有分组
2. 追加缺失的分组
3. 按 name 去重，追加缺失的指令

## 7. 指令执行流程

### 7.1 执行流程

```
用户输入角色ID + 点击按钮
        ↓
将 %s / % 替换为角色ID
（支持空格分隔多个ID，自动生成多行指令）
        ↓
chrome.scripting.executeScript 注入GM页面
        ↓
在 document 中查找 #ctl_gmcmd 输入框
        ↓
填写指令 → 触发 input/change/blur 事件
→ 触发 jQuery autocomplete
        ↓
若勾选「自动执行」→ 自动点击 #ctl_run
        ↓
记录到历史 → Toast 通知
```

### 7.2 目标元素

| 元素 | 选择器 |
|------|--------|
| GM 命令输入框 | `#ctl_gmcmd` |
| 执行按钮 | `#ctl_run` |
| 游戏主 iframe | `iframe#ifa`, `iframe[name="ifa"]`, `iframe.iframe`, `iframe.ifa` |

### 7.3 多角色ID支持

输入 `1001 1002 1003`，指令模板 `add_item %s 90001 99999`，展开为：
```
add_item 1001 90001 99999
add_item 1002 90001 99999
add_item 1003 90001 99999
```

### 7.4 多目标查找策略

1. 优先在主 document 中查找
2. 查找 iframe：同域名 iframe 优先于跨域 iframe
3. 逐个 iframe 尝试注入，直到找到 `#ctl_gmcmd` 元素

## 8. 历史记录模块

### 8.1 记录内容

每条历史记录包含：
- 指令名称
- 指令内容
- 当时使用的角色ID（可编辑）
- 执行时间
- 来源 Tab（通用/个人）

### 8.2 特性

- 最多保存 100 条（超出自动截断）
- 同名+同ID组合自动去重（更新时间戳移到顶部）
- 可编辑角色ID，实时预览替换后的指令
- 快速执行：点击即用当前输入框的ID重新执行

## 11. 后端 API 对接

### 11.1 接口地址
`http://10.30.138.5:3000`

### 11.2 超时处理
请求超时 5 秒，超时后自动 fallback。

### 11.3 接口列表

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/health` | 健康检查 |
| GET | `/api/commands/public` | 获取公开通用指令 |
| POST | `/api/commands/public` | 保存公开通用指令 |
| GET | `/api/commands/:owner` | 获取个人指令 |
| POST | `/api/commands` | 保存个人指令 |
| DELETE | `/api/commands/:owner` | 删除个人指令 |
| GET | `/api/categories/:owner` | 获取个人分组 |
| POST | `/api/categories` | 保存个人分组 |
| POST | `/api/dedup` | 清理重复记录 |
