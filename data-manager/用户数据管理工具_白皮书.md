## 1. 项目概述

### 1.1 工具定位

GM 数据管理工具是一个浏览器单文件 HTML 工具，用于管理 GM 指令数据。核心操作对象是 **owner**（用户标识），每个 owner 在 `userdata` 表中存储一条 JSON 记录。

### 1.2 核心功能

- **查询**：按 owner 名称查询对应 JSON 指令数据
- **编辑**：在 JSON 编辑器中修改指令内容并保存
- **新增**：通过搜索栏输入新 owner 名称创建记录
- **重命名**：修改 owner 名称（UPDATE SQL）
- **删除**：删除指定 owner 的记录
- **导入/导出**：JSON 文件导入导出
- **缓存**：首次加载全量预热，切换 owner 无延迟

## 3. 核心功能详解

### 3.1 全量预热缓存

页面首次加载时调用 `/api/commands/list?limit=10000&full=1`，后端返回所有 owner 的完整 JSON 数据，前端一次性写入内存缓存（`ownerCache`）。后续切换 owner 直接从内存读取，零网络延迟。

**缓存数据结构**：
```javascript
const ownerCache = {}; // { owner: { display: formattedJson } }
```

### 3.2 查询

1. 检查 `ownerCache`，命中则直接渲染
2. 未命中则请求 `/api/commands/:owner`
3. 请求完成后写入缓存
4. 成功后在左侧列表中高亮对应条目

### 3.3 重命名 Owner

1. 点击"✏️ 重命名"按钮
2. `prompt` 输入新名称
3. 调用 `PUT /api/commands/rename` 执行 `UPDATE userdata SET owner = $1 WHERE owner = $2`
4. 成功后更新缓存键、左侧列表文本、编辑器标题、搜索栏输入框

### 3.4 删除

**编辑器删除按钮**：调用 `DELETE /api/commands/:owner`，成功后清空编辑器状态并从缓存和列表移除。

**列表删除按钮**：点击列表中的 × 按钮，同样调用后端 API 真正删除数据。

### 3.5 缓存一致性

| 操作 | 缓存行为 |
|------|---------|
| 首次加载 | 全量预热 |
| 查询 | 命中则跳过网络 |
| 保存 | 同步更新缓存 |
| 删除 | 清除缓存条目 |
| 重命名 | 迁移缓存键 |

## 4. 后端 API

### 4.1 接口列表

| 方法 | 路径 | 说明 |
|------|------|------|
| GET | `/api/commands/list?limit=&offset=&full=` | 列出所有 owner，`full=1` 返回完整数据 |
| GET | `/api/commands/:owner` | 获取单个 owner 的 JSON 数据 |
| PUT | `/api/commands/rename` | 重命名 owner |
| POST | `/api/commands` | 新增/保存 owner 的 JSON 数据 |
| DELETE | `/api/commands/:owner` | 删除 owner |
| GET | `/api/commands/public` | 获取 public 指令 |
| POST | `/api/commands/public` | 保存 public 指令 |
| GET | `/api/categories/:owner` | 获取个人分组 |
| POST | `/api/categories` | 保存个人分组 |
| POST | `/api/dedup` | 清理重复 owner |
| GET | `/api/health` | 健康检查 |

### 4.2 关键接口详情

**PUT /api/commands/rename**
```json
// Request
{ "oldOwner": "player_001", "newOwner": "player_002" }

// Response
{ "success": true, "oldOwner": "player_001", "newOwner": "player_002", "written": { "mysql": true, "postgresql": true } }
```

**GET /api/commands/list?full=1**
```json
// Response
{
  "code": 0,
  "data": {
    "owners": [
      { "owner": "player_001", "commands": "{...}", "updated_at": "..." },
      { "owner": "public", "commands": "{...}", "updated_at": "..." }
    ],
    "total": 100,
    "limit": 10000,
    "offset": 0
  }
}
```

### 4.3 双库双写

后端同时连接 MySQL 和 PostgreSQL（双库模式），写操作通过 `db.write()` 同时写入两个数据库，确保数据一致性。

### 4.4 打包

后端使用 `pkg` 打包为单文件 exe：
```bash
npm run pkg  # → gm-backend.exe (node14-win-x64)
```

## 5. 数据结构

### 5.1 userdata 表

```sql
-- MySQL
CREATE TABLE userdata (
  id INT AUTO_INCREMENT PRIMARY KEY,
  owner VARCHAR(255) NOT NULL UNIQUE COMMENT '用户名',
  commands TEXT COMMENT '个人指令 JSON',
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
) ENGINE=InnoDB DEFAULT CHARSET=utf8mb4;

-- PostgreSQL
CREATE TABLE userdata (
  id SERIAL PRIMARY KEY,
  owner VARCHAR(255) NOT NULL UNIQUE,
  commands TEXT,
  created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP
);
```

## 8. 傻瓜式使用方法

### 8.1 启动

1. **启动后端**：双击运行 `gm-backend.exe`（后端服务，保持运行不要关闭）
2. **打开前端**：双击 `data-manager.html`（用浏览器打开，建议 Chrome）
3. **确认连接**：页面右上角状态显示"✓ 已连接"即表示正常

### 8.2 查询数据

1. 在左侧列表中找到要操作的 owner，点击选中（高亮蓝色）
2. 右侧编辑器自动加载该 owner 的 JSON 数据
3. 也可以在顶部搜索栏输入 owner 名称，回车查询

### 8.3 编辑数据

1. 在右侧 JSON 编辑器中修改内容
2. 点击 **💾 保存到 DB**（或按 `Ctrl+S`）
3. 看到"数据已保存到数据库"提示即完成

### 8.4 新增 owner

1. 在顶部搜索栏输入新的 owner 名称
2. 回车，右侧编辑器会显示空 JSON `{}`
3. 编辑内容后保存即可自动创建新记录

### 8.5 重命名 owner

1. 选中要重命名的 owner
2. 点击编辑器标题区的 **✏️ 重命名**
3. 在弹窗中输入新名称，确定即可

### 8.6 删除 owner

1. 选中要删除的 owner
2. 点击编辑器标题区的 **🗑️ 删除**
3. 确认后该 owner 从数据库中彻底删除

### 8.7 导出 / 导入

- **导出**：查询到目标 owner 后，点击 **📥 导出**，下载 JSON 文件
- **导入**：点击 **📤 导入**，选择本地 JSON 文件，导入到编辑器

### 8.8 搜索过滤

在顶部搜索栏输入文字，左侧 owner 列表会实时过滤显示匹配项。
